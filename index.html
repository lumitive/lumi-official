為什麼是現在

1998 到 2023，顧客用搜尋框找你。
現在，顧客問的是 AI。

當顧客對 AI 說「旺角附近邊間米線好食」，決定答案的不再是你的 SEO，而是你的菜單對 agent 是否可讀、你的下單接口對 agent 是否可用。

舊的鏈路 · 你擁有渲染權

  1. 01顧客打開搜尋框
  2. 02排名決定他看到誰
  3. 03他點進你的頁面
  4. 04你的頁面說服他下單

二十年的工具全部掛在這條鏈上：關鍵詞、反向連結、落地頁、轉化率。

新的鏈路 · 「點擊」沒有發生

  1. 01顧客跟 agent 講一句話
  2. 02agent 自己揀一個品牌
  3. 03他點進你的頁面
  4. 04agent 直接落單，摘要一句講完

agent 判斷的是：哪個品牌菜單準、哪個接口可靠、哪個不會出錯。這一層，通常冇人負責。

三筆帳

把每一個百分點，
算成一個數字。

拉下面的滑桿，用你自己的規模算。只算最保守的那一筆 —— 省下的抽成；復購和高峰承接要你的真實數據才算得準。

01 · 渠道奪回

省下抽成

平台訂單每遷移一個百分點到自有渠道，省下的就是那一單的抽成。三筆帳裡唯一不需要假設行為改變的一筆。

02 · 熟客復購

「老樣子」兩個字能成立，顧客就冇理由返平台重新找你。口徑：同一 user_id 的 30 天復購次數。

不排隊、不漏單

午市高峰的併發唔需要加人頭。口徑：峰值小時完成單量 ÷ 當班人數。

邊界

它可以推薦，
但它不能定價。

三個最容易上新聞的事故，在架構裡就冇留下入口。不是靠提示詞叮囑模型，是服務端冇那條路徑。

價格
模型報的價不作數。 最終金額由你的後端重新計算。模型算錯了，顧客付的也是對的那個數。
過敏與忌口
親口聲明過的忌口是黑名單，不是提示。 服務端硬攔。推斷出來的偏好（「他好像唔太食辣」）永遠唔會進入這條安全鏈。
落單
下單必須顧客親手確認。 「幫我落單啦」這句話本身不構成確認 —— 系統不接受從語氣推斷出來的同意。
醫療
命中醫療語境就停止生成。 固定免責 + 轉真人。不會有一段即興寫出來的健康建議掛在你的品牌下面。

熟客記憶

平台把你的顧客，
變成了平台的顧客。

在平台上，顧客記住的是平台的介面。在你自己的渠道上，被記住的是他 —— 而記住他的那份資料，在你自己的庫裡。

他講過的，算數

聲明過的忌口、口味、上次那碗的全部配置。四層記憶分開存：當前對話、長期畫像、訂單流、語義召回。

他冇講過的，不算數

推斷出來的偏好只用來讓對話順，標著信心值，永遠不會被當成他講過的話來用。

他要刪，就真的刪

一個接口刪到底，跨所有記憶層。之後 agent 看到的是一個陌生人，向量庫裡也召不回來。

每間店賣的不一樣

分店缺貨、限定、區域定價，按店生效。顧客揀了哪間店，看到的就是那間店真實有的東西。

招牌屬於品牌

語氣、問候、品牌用字由品牌定義，不會因為顧客換了一間店就變一個人。

集團多品牌

每個品牌一份配置檔，資料從第一天就按品牌隔離。加一個品牌是加一份配置，不是再做一個項目。

信任與合規

你的法務會問的四件事。

資料放哪

顧客資料寫進你指定的庫，地區可指定。我們不做資料轉售，不跨租戶訓練。

刪除權

顧客要求刪除，一個接口跨所有記憶層生效；審計記錄按法規保留，agent 側即刻睇唔到。

可審計

每一次下單都能回溯：調用了哪些工具、價格從哪裡算出、哪條約束在生效。

我們不做什麼

不替顧客下單、不替顧客付款、不給醫療建議、不在你冇點頭前改任何對外文案。
